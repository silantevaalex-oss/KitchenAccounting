# KitchenAccounting

Локальное PWA-приложение для учёта обработки продуктов на кухне. Работает в браузере, сохраняет записи на устройстве и поддерживает резервное копирование и синхронизацию с Google Sheets.

## Возможности

- Запись фактического и планового выхода, количества и веса единиц.
- Журнал обработок, справочник продуктов, ингредиенты и технологические карты.
- Статистика, график выхода, экспорт CSV и PDF.
- Резервное копирование и восстановление данных.
- Необязательная синхронизация с Google Sheets.

## Запуск

Откройте опубликованную версию: https://silantevaalex-oss.github.io/KitchenAccounting/

Для локальной разработки нужен Node.js 22+:
1. Клонируйте репозиторий.
2. Запустите локальный статический сервер из корня проекта (например, `npx serve .`).
3. Откройте показанный адрес в браузере. Для Service Worker требуется localhost или HTTPS.

## Проверки

Автоматические тесты выполняются командой:

```bash
npm test
```

GitHub Actions запускает их при push в main/ветку укрепления и при создании Pull Request в main.

## Структура

- `app.js` — связывает интерфейс, хранение, техкарты и Google Sheets.
- `js/core.js` — чистые функции расчётов, нормализации и форматирования.
- `js/reports.js` — агрегирование данных отчётов.
- `js/storage.js` — безопасное чтение локального JSON-хранилища.
- `js/sync-merge.js` — проверяемое объединение версий при синхронизации.
- `test/` — автоматические тесты бизнес-логики.
- `icon.svg` — единая масштабируемая иконка приложения и favicon.
- `sw.js` — сетевой кэш и офлайн-резерв.

## Важные правила данных

- Фактический выход рассчитывается как фактический выход записи плюс количество единиц, умноженное на вес одной единицы.
- Не удаляйте локальное хранилище браузера, если в нём есть несинхронизированные данные.
- Перед первым включением синхронизации на устройствах создайте резервные копии и убедитесь, что они сохранены.
- Google OAuth и идентификатор таблицы находятся в приложении; не публикуйте личные токены доступа.
